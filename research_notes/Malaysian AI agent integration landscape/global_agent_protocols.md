# Global AI-Agent Connectivity Standards & Infrastructure (state as of mid-October 2026) — implications for a Malaysia "agent action layer"

Research date: 2026-10-15. Each claim is dated where the source allows. "Primary" means the spec body, vendor docs or the company's own announcement. Several primary domains (modelcontextprotocol.io, developers.openai.com, arcade.dev, zapier.com, visa.com) did not resolve from the research environment, so some claims rely on secondary sources. Those are flagged.

## 1. MCP specification: latest version, key features, governance, transports, SDKs

### Takeaway
As of Oct 2026 the current MCP revision is **2026-07-28**, the largest change since launch. Its release candidate was locked on 21 May 2026 and the final spec shipped 28 July 2026. It makes the protocol **stateless**: no initialize handshake and no session IDs. It moves **MCP Apps** (UI) and **Tasks** (long-running work) into a formal Extensions framework. It prefers **Client ID Metadata Documents (CIMD)** over Dynamic Client Registration, and it deprecates Roots, Sampling and Logging. Governance is vendor-neutral: MCP was donated to the Linux Foundation's **Agentic AI Foundation (AAIF)** on 9 Dec 2025, and A2A joined AAIF in Aug 2026. Client adoption of the new revision lags server and SDK adoption.

### Cited Findings
**Version history and feature lineage (older revisions flagged)**
- **2025-06-18 revision (older; still the baseline many clients run):** added elicitation (form mode), **structured tool output** (`structuredContent` alongside `content`), and **resource links** in tool results — [Microsoft .NET blog, Jul 22 2025](https://devblogs.microsoft.com/dotnet/mcp-csharp-sdk-2025-06-18-update/); [Logtalk MCP docs](https://logtalk.org/apis/mcp_tool_protocol_0.html)
- **2025-11-25 revision (older):** added **URL-mode elicitation**, meant for "auth flows, payment processing, and other sensitive or secure operations" but explicitly *not* for authorizing the MCP client's access to the server, which MCP authorization handles — [MCP draft spec mirror: elicitation](https://modelcontextprotocol.net/specification/draft/client/elicitation); [Vercel explainer](https://vercel.com/i/mcp-elicitation-form-vs-url-mode). It also defined CIMD: Claude's docs link CIMD to `specification/2025-11-25/basic/authorization#client-id-metadata-documents` — [Claude docs: Authentication, fetched Oct 2026](https://claude.com/docs/connectors/building/authentication). It introduced an experimental **Tasks** API, which the 2026-07-28 revision replaces — [MCP blog, RC post](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)
- **2026-07-28 timeline:** the RC was locked on **21 May 2026**, the final spec followed on **28 July 2026**, and there was a 10-week validation window for SDK maintainers and clients — [MCP blog (primary)](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/). Secondary write-ups describe it as the "biggest MCP spec update" — [WorkOS](https://workos.com/blog/mcp-2026-spec-agent-authentication); [Scalekit](https://www.scalekit.com/blog/mcp-spec-update-july-2026)

**2026-07-28 key changes (from the primary MCP blog unless noted)** — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)
- **Stateless core:** the `initialize`/`initialized` handshake is removed (SEP-2575). Protocol version, client info and capabilities travel in `_meta` on every request, and a new `server/discover` method returns server capabilities. `Mcp-Session-Id` and protocol-level sessions are removed (SEP-2567), so any instance can serve any request without sticky routing. Application state is carried by **explicit handles the tool returns** (e.g., a `basket_id`), which the model passes back on later calls.
- **Streamable HTTP transport:** requires `Mcp-Method` and `Mcp-Name` headers (SEP-2243), and servers must reject requests whose headers and body disagree. List and read results carry `ttlMs` and `cacheScope` (SEP-2549, modelled on HTTP Cache-Control). W3C Trace Context (`traceparent`, etc.) keys in `_meta` are documented (SEP-414).
- **Server-to-client requests:** Multi Round-Trip Requests (SEP-2322) replace held-open SSE streams. The server returns an `InputRequiredResult`, and the client retries with `inputResponses` plus the echoed `requestState`. Server-initiated requests such as elicitation are allowed **only while the server is processing a client request** (SEP-2260, now MUST).
- **Authorization:** clients MUST validate `iss` per RFC 9207 (SEP-2468). Clients declare OIDC `application_type` during DCR (SEP-837). Registered credentials are bound to the issuer, and clients re-register if the resource moves to another authorization server (SEP-2352). The spec also covers refresh-token requests to OIDC servers (SEP-2207) and clarifies step-up **scope accumulation** (SEP-2350) and the `.well-known` suffix (SEP-2351).
- **CIMD preferred, DCR deprecated:** secondary sources say 2026-07-28 deprecates DCR in favor of CIMD, keeping DCR as a fallback — [WorkOS](https://workos.com/blog/mcp-client-identity-dcr-cimd-auth-md); [Alpic](https://alpic.ai/blog/the-july-2026-mcp-release-changes-how-ai-assistants-sign-users-into-mcp-apps). The spec's client-registration page lists **three mechanisms (CIMD, pre-registration, DCR)**. A CIMD `client_id` is an https URL with a path, and the document's `client_id` must match the URL exactly — [MCP spec 2026-07-28 client-registration](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization/client-registration.md). The normative reference is an IETF *draft* (draft-ietf-oauth-client-id-metadata-document), not an RFC — [Hidekazu Konishi analysis](https://hidekazu-konishi.com/entry/which_mcp_clients_a_remote_mcp_server_lets_in.html) (secondary).
- **Extensions framework (SEP-2133):** reverse-DNS extension IDs, an `extensions` capability map, separate `ext-*` repos, independent versioning, and a new Extensions Track.
- **MCP Apps (SEP-1865):** servers ship **sandboxed HTML UIs**. Tools declare UI templates in advance, and UI actions go over the same JSON-RPC path as tool calls. Secondary sources say MCP Apps became the first official, stable extension on **26 Jan 2026**. It uses `ui://` resources with MIME type `text/html;profile=mcp-app`, mandatory iframe sandbox plus CSP, and is co-authored by Anthropic and OpenAI maintainers. Reported hosts include Claude, ChatGPT, Cursor, Goose and VS Code — [Morph](https://www.morphllm.com/mcp-apps); [nanoHUB docs](https://nanohub-mcp.readthedocs.io/en/latest/skill/references/mcp-apps.html). Sources disagree on whether the number is SEP-1724 or SEP-1865; the primary blog says SEP-1865.
- **Tasks:** graduates from experimental core to an extension. `tools/call` can return a task handle, which clients manage with `tasks/get`, `tasks/update` and `tasks/cancel`. `tasks/list` is removed, and users of the 2025-11-25 Tasks API must migrate.
- **Deprecations (SEP-2577):** **Roots**, **Sampling** (replaced by direct LLM provider API calls) and **Logging** (replaced by stderr or OpenTelemetry). A formal lifecycle policy (SEP-2596) guarantees at least 12 months between deprecation and removal. SEP-2484 requires a conformance-suite scenario before a Standards-Track SEP becomes Final.
- **Tool schemas:** full **JSON Schema 2020-12** for `inputSchema`/`outputSchema` (SEP-2106), and implementations MUST NOT auto-dereference external `$ref`. The missing-resource error code changes from -32002 to -32602 (SEP-2164).
- **Form vs URL elicitation:** one secondary source says the 2026-07-28 text **prohibits form-mode elicitation for passwords, API keys, access tokens and payment credentials**, which must go through URL mode — [yage.ai, Jul 16 2026](https://yage.ai/share/mcp-elicitation-human-in-loop-en-20260716.html) (not verified against spec text).
- **SDK tiers:** a new tier system (PR 1777) scores official SDKs against the conformance suite, and Tier-1 SDKs were expected to ship 2026-07-28 support within the 10-week window — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/).

**Adoption of the new revision (lagging)**
- A compatibility matrix found that only **2 of 22** tracked client/SDK rows supported 2026-07-28: **MCP Inspector 2.0.0** and **MCP Python SDK 2.0.0**. Server support is ahead of client support — [Hidekazu Konishi](https://hidekazu-konishi.com/entry/which_mcp_clients_a_remote_mcp_server_lets_in.html) (secondary, mid-2026).
- Google's Agent Platform docs explicitly describe the 2026-07-28 change from a "bidirectional, stateful protocol to a stateless protocol" — [Google Cloud docs](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/use-agent-platform-mcp).
- One guide says Copilot Studio's docs did not yet claim 2026-07-28 support — [Babybots guide](https://www.babybots.ai/guides/connect-copilot-studio-agents-mcp-2026) (secondary; not verified with Microsoft).

**Governance**
- On **9 Dec 2025**, Anthropic donated MCP to the **Agentic AI Foundation (AAIF)**, a directed fund under the Linux Foundation. AAIF was co-founded by Anthropic, Block and OpenAI, with support from Google, Microsoft, AWS, Cloudflare and Bloomberg. The launch projects were MCP, Block's **goose** and OpenAI's **AGENTS.md** — [Anthropic (primary)](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation); [SD Times](https://sdtimes.com/ai/linux-foundation-forms-agentic-ai-foundation-to-be-new-home-for-mcp-goose-and-agents-md/)
- At donation (Dec 2025), Anthropic cited **10,000+ active public MCP servers** and adoption by ChatGPT, Cursor, Gemini, Microsoft Copilot and VS Code — [Anthropic](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation). The widely repeated **97M+ monthly SDK downloads** (Python plus TypeScript) also dates to Dec 2025. Later 2026 figures, such as ~200M monthly npm downloads for `@modelcontextprotocol/sdk` in Aug 2026 and a claim of "400M", come from secondary stats roundups and are unverified — [DigitalApplied stats roundup](https://digitalapplied.com/blog/mcp-adoption-statistics-2026); [DreamFactory](https://www.dreamfactory.com/hub/mcp-server-statistics)

**Registry**
- The official MCP Registry (registry.modelcontextprotocol.io) launched in **preview on 8 Sep 2025**. Its maintainers include Anthropic, GitHub, PulseMCP and Microsoft — [MCP Registry preview post](https://modelcontextprotocol.info/blog/mcp-registry-preview/). Its API froze at v0.1 on 24 Oct 2025 ahead of v1/GA. Third-party guides from mid-2026 still describe it as **preview**, and I found **no GA announcement** — [QVeris guide](https://qveris.ai/guides/mcp-registry/); [Atlan](https://atlan.com/know/ai-agent/what-is-an-mcp-registry/)
- VS Code has added MCP registry and allowlist controls for enterprises (public preview) — [MacMyths](https://macmyths.com/vs-code-stables-mcp-registry-and-allowlist-controls-are-in-public-preview/) (secondary).

**stdio vs remote**
- Claude's directory **no longer accepts local servers packaged as MCPB**, and desktop-extension listings are deprecated. Local servers must ship inside a "plugin", while remote servers must be HTTPS — [Claude docs: Submit a connector](https://claude.com/docs/connectors/building/submission)
- Copilot Studio supports **only Streamable HTTP**, and SSE stopped being supported after Aug 2025 — [Babybots](https://www.babybots.ai/guides/connect-copilot-studio-agents-mcp-2026); [mcpstepbystep](https://mcpstepbystep.com/learn/copilot-studio/) (secondary)

### Inferences
- A new Malaysian action layer should build **natively on 2026-07-28 semantics** (stateless, explicit handles, Tasks extension, MRTR, CIMD), because horizontal scaling and serverless deploys become much simpler. It must also **stay backward-compatible with 2025-06-18/2025-11-25 clients** (session-based Streamable HTTP, DCR), because client adoption of 2026-07-28 was thin as of mid-2026.
- Remote, OAuth-protected Streamable HTTP is now the de facto distribution unit. stdio is relegated to developer and local tooling.
- MCP Apps plus URL-mode elicitation give a standard way to render **confirmation and preview UIs** and to hand off to secure external pages (e.g., FPX/DuitNow bank redirects, MyDigital ID login) without putting credentials in chat.

### Gaps
- Could not load modelcontextprotocol.io directly (DNS failure), so SEP details come from the official MCP blog plus secondary write-ups. The exact 2026-07-28 changelog text was not verified.
- No official 2026 figure for server count or SDK downloads was found. The best primary data is from Dec 2025.
- Official SDK status not verified: Python SDK 2.0.0 is reported, FastMCP's integration into the official Python SDK is not confirmed in these sources, and the TypeScript SDK's 2026-07-28 release status is not confirmed.

## 2. Client distribution: which AI clients consume remote MCP, how businesses install them, directory listing requirements

### Takeaway
All major assistants consume remote MCP: Claude, ChatGPT, Gemini Enterprise, Microsoft Copilot Studio, Cursor and VS Code. Two **app-store-style directories** matter most. The first is **Claude's Connectors Directory**, which has a self-serve developer portal, auto-listing as "Community" with optional "Verified" review, and is open to any paid plan. The second is **ChatGPT's app directory** (Apps SDK, OpenAI review, country targeting). Claude's directory policy has two rules that directly constrain a Malaysian aggregator. It **does not accept connectors that transfer money or financial assets**. It also requires that the server **call your own first-party APIs or APIs you legitimately proxy**, with the server domain matching your service.

### Cited Findings
**Claude (primary docs, fetched Oct 2026)**
- Submission runs through the developer portal at claude.ai/directory/manage under "MCP connector". **Anyone on a paid Claude plan can submit.** Remote servers must be HTTPS. Local servers can be distributed only inside a plugin, and Skills ship only inside plugins — [Claude docs: Submit](https://claude.com/docs/connectors/building/submission). Older third-party guides said Team/Enterprise Owners only, which conflicts with the current docs — [MCPJam](https://www.mcpjam.com/blog/publish-mcp-server-claude-connectors-directory).
- Requirements: meet Anthropic's security standards. Every tool needs a `title` plus `readOnlyHint` or `destructiveHint`. Use OAuth 2.0 for authenticated services. Provide docs, privacy policy, support contact, icon, and a **fully populated test account** for reviewers. MCP Apps need 3–5 PNG carousel screenshots. There are seven compliance acknowledgments, covering directory guidelines, **first-party API usage**, **financial transactions**, AI media generation, prompt injection, conversation-data collection and public docs — [Claude docs: Submit](https://claude.com/docs/connectors/building/submission)
- The portal asks whether the underlying API is **"your own, proxied from a partner with permission, or a third party's you don't control"**, and whether the connector handles personal health data — [Claude docs: Submit](https://claude.com/docs/connectors/building/submission)
- Review: an automated policy scan, then **default listing as a Community connector**. Listings flagged as highly useful can be escalated to slower "Verified" review with functional tests of each tool — [Claude docs: Review criteria](https://claude.com/docs/connectors/building/review-criteria)
- **Unsupported use cases:** connectors that "transfer money, cryptocurrency, or other financial assets", and connectors that generate images, video or audio through AI models. **API ownership:** "Your server must call your own first-party APIs, or APIs you legitimately proxy. The MCP server domain should match your service." — [Claude docs: Review criteria](https://claude.com/docs/connectors/building/review-criteria)
- Supported auth types: `oauth_dcr` (default), `oauth_cimd` (default), `oauth_anthropic_creds` (by arrangement), `custom_connection` (customer enters their own URL or OAuth client), `static_headers` (org-level API key, beta, limited orgs) and `none`. Per-customer URL patterns are supported, e.g. `^https://[a-z0-9-]+\.mcp\.example\.com/mcp$`. For high-traffic servers Anthropic recommends **CIMD or Anthropic-held credentials over DCR**, because "DCR causes Claude to register a new client on every fresh connection". Machine-to-machine `client_credentials` is **not** supported. "Enterprise Managed Auth" lets SSO identity assertions replace the consent screen. The same auth infrastructure serves claude.ai, Desktop, mobile, Claude Code and Cowork — [Claude docs: Authentication](https://claude.com/docs/connectors/building/authentication)

**ChatGPT (OpenAI)**
- Apps in ChatGPT and the **Apps SDK** (built on MCP) were introduced in Oct 2025 (older). Pilot partners included Booking.com, Canva, Coursera, Expedia, Figma, Spotify and Zillow. Developers need clear privacy policies and data minimization, and higher-quality apps may be featured — [OpenAI](https://openai.com/index/introducing-apps-in-chatgpt/)
- **Third-party submissions and an in-ChatGPT app directory opened 17 Dec 2025.** A submission includes MCP connectivity details, testing instructions, directory metadata and **country availability** settings. OpenAI reviews each app — [OpenAI](https://openai.com/index/developers-can-now-submit-apps-to-chatgpt/); [VentureBeat](https://venturebeat.com/technology/openai-now-accepting-chatgpt-app-submissions-from-third-party-devs-launches)
- A Sept 2026 guide lists the listing requirements as icon, name/description, screenshots, privacy policy, support contact, **verified website** and MCP server details — [dforce](https://dforce.com.ua/en/blog/how-to-build-a-chatgpt-app/) (secondary). A developer write-up says apps are expected to use **OAuth 2.1**, with no-auth allowed only for tools that don't touch user data — [3Min API](https://3minapi.com/blog/building-chatgpt-app-with-apps-sdk) (secondary)
- Monetization: in Jan 2026, apps selling digital goods could not be submitted — [OpenAI community forum](https://community.openai.com/t/chatgpt-app-monetization-apps-sdk/1372343/4). A Sept 2026 guide says the GA route is **external checkout** for physical goods, where the purchase completes on the merchant's site — [Snaplama](https://www.snaplama.com/blog/how-to-create-chatgpt-apps-and-monetize-them-complete-2026-guide) (secondary, unverified)
- Apps were not available in the EEA, Switzerland or the UK at launch. This may be outdated — [ChatGPT Apps SDK guide](https://umesh-malik.com/blog/chatgpt-apps-sdk-super-app-guide) (secondary)

**Google**
- **Gemini Enterprise Agent Platform** launched a **remote MCP server** around 30 Jun–1 Jul 2026, using OAuth 2.0 plus IAM and enabled automatically with the Agent Platform API — [IT Brief Asia](https://itbrief.asia/story/google-launches-remote-mcp-server-for-gemini-enterprise); [Google Cloud docs](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/use-agent-platform-mcp)
- Gemini Enterprise can register **custom MCP servers** (configured as a custom data store in the Google Cloud console) but doesn't ship connectors for every source — [Coupler.io](https://blog.coupler.io/gemini-enterprise-mcp/) (secondary)
- Gemini CLI supports MCP server configuration and Agent Skills — [GitHub gemini-cli discussion](https://github.com/google-gemini/gemini-cli/discussions/1912)

**Microsoft Copilot Studio**
- Remote MCP servers have been consumable as agent tools since GA in **May 2025**. **Tools are supported, resources only in limited cases, prompts not at all.** Only Streamable HTTP is supported — [Babybots](https://www.babybots.ai/guides/connect-copilot-studio-agents-mcp-2026); [mcpstepbystep](https://mcpstepbystep.com/learn/copilot-studio/) (secondary)

**Coding clients and MCP Apps hosts**
- MCP Apps render inline in Claude Desktop, ChatGPT, Cursor, Goose and VS Code. Named launch partners include Figma, Canva, Slack and Salesforce — [Morph](https://www.morphllm.com/mcp-apps) (secondary)

### Inferences
- **Distribution implication for a Malaysian hub:** a single "Malaysia hub" connector that proxies many third-party Malaysian APIs (banks, LHDN MyInvois, SSM, e-wallets) may clash with Claude's **"first-party API / legitimately proxy"** rule and the **"no money transfer"** rule. Mitigations are (a) written partner permissions or white-label "powered-by" connectors on partner domains, (b) value-add tools such as compliance logic, invoice validation and drafting rather than raw API passthrough, and (c) prepare-only payment flows where the agent prepares and the user executes on a bank or wallet page via URL elicitation. This is an inference; check with Anthropic's review team (mcp-review@anthropic.com).
- Unlike Claude, ChatGPT exposes explicit **country availability** settings. A Malaysia-specific app can geo-target, but whether ChatGPT apps are available in Malaysia was not confirmed.
- Enterprise channels (Copilot Studio, Gemini Enterprise) install MCP servers by admin URL and do not use consumer directories. For B2B in Malaysia (M365-heavy SMEs and corporates), a **Copilot Studio-compatible tools-only server** is a major distribution path.

### Gaps
- Could not reach developers.openai.com, so OpenAI's current official submission and review policy (including financial-transaction rules equivalent to Claude's) is unverified.
- Not found: how many apps are in the ChatGPT directory or connectors in Claude's directory; consumer Gemini app (non-Enterprise) support for third-party remote MCP; Cursor's directory/marketplace model.
- Not found: Malaysia-specific availability of ChatGPT apps or Claude connectors.

## 3. Adjacent protocols: A2A, agentic commerce/payments, Agent Skills, AGENTS.md — which are gaining adoption

### Takeaway
By late 2026 the stack has stratified. **MCP** covers tools and data. **A2A** covers agent-to-agent hand-off: v1.0 shipped in spring 2026 and the project joined AAIF in Aug 2026, but field deployment is contested. **Agent Skills/SKILL.md** (Dec 2025, adopted by 30+ tools) and **AGENTS.md** (AAIF) cover instructions. Commerce is the messiest layer. **Google's UCP** (Jan 2026) gained the broadest coalition, OpenAI **scaled back Instant Checkout/ACP** in Mar 2026, **x402** leads stablecoin micropayments, and the card networks' **agent tokenization** (Mastercard Agent Pay, Visa Intelligent Commerce/TAP) is **already piloting in Malaysia**.

### Cited Findings
**A2A (Agent2Agent)**
- Google handed A2A to the Linux Foundation on **23 Jun 2025** (older) — [BlckAlpaca](https://blckalpaca.at/en/knowledge-base/ai-agents/a2a-protocol-basics/linux-foundation-aaif-bedeutung)
- **v1.0 (stable)** shipped in **Mar or Apr 2026** (sources differ). Reports cite 150+ supporting organizations, Signed Agent Cards, and three bindings: JSON-RPC 2.0/HTTPS, gRPC and HTTP+JSON/REST — [Bex](https://bex.co/blog/2026/07/11/a2a-v1-linux-foundation-deploy-agent-handshake); [Stellagent](https://stellagent.ai/insights/a2a-protocol-google-agent-to-agent)
- A2A **joined AAIF in Aug 2026**; sources give the 17th, 20th or 27th, the last "as a growth-stage project" — [Enterprise DNA](https://enterprisedna.co/resources/news/google-a2a-aaif-agent-protocol-open-standard-august-2026/); [Pebblous](https://blog.pebblous.ai/blog/a2a-mcp-agentic-ai-foundation-authorization/en/); [FlowHunt](https://www.flowhunt.io/blog/agentic-ai-foundation-a2a-mcp-standards/)
- Skeptical view: A2A is "barely implemented in the field" — [Heym](https://heym.run/blog/a2a-vs-mcp)

**Agent Skills (SKILL.md) and AGENTS.md**
- Anthropic published Agent Skills as an open standard at agentskills.io in **Dec 2025** (one source says 18 Dec). OpenAI (ChatGPT, Codex) and Microsoft adopted it within days or weeks, and Google Gemini CLI by Jan 2026. More than **30 tools** had adopted it by Apr 2026, including GitHub Copilot, Cursor, JetBrains Junie and VS Code. A skill is a folder with `SKILL.md` (YAML frontmatter) plus optional scripts, references and assets — [Daniel Vaughan](https://codex.danielvaughan.com/2026/05/05/agent-skills-open-standard-portable-skills-codex-cli-cross-agent/); [Noqta](https://noqta.tn/en/news/skill-md-open-standard-30-ai-coding-tools-adoption-2026); [Denser](https://denser.ai/blog/agent-skills-guide/) (all secondary; counts vary)
- In Claude's directory, Skills are not a standalone submission type and ship inside plugins — [Claude docs](https://claude.com/docs/connectors/building/submission)
- AGENTS.md (OpenAI) was a founding AAIF project, Dec 2025 — [Anthropic](https://www.anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation)

**Agentic commerce/checkout**
- **Google Universal Commerce Protocol (UCP):** launched **11 Jan 2026** at NRF, co-developed with Shopify, Etsy, Wayfair and Target, and endorsed by 20+ partners including Visa, Mastercard, Stripe and AmEx — [CNBC](https://www.cnbc.com/2026/01/11/google-launches-universal-commerce-protocol-bets-on-ai-powered-retail.html). Its technical council expanded to 10 members on **24 Apr 2026** when Amazon, Meta, Microsoft, Salesforce and Stripe joined — [Ken Huang Substack](https://kenhuangus.substack.com/p/googles-ucp-just-won-agentic-commerce) (secondary). Cart support and catalog access were added in Mar 2026, and **Universal Cart** (cross-merchant) was announced at I/O on 19 May 2026 — [Azoma](https://www.azoma.ai/insights/google-i-o-2026-what-the-agentic-commerce-announcements-mean-for-brands). Checkout is **US-first**, through AI Mode, Gemini and YouTube Shopping, with Canada, Australia and the UK slated for end-2026. Google Pay is the main payment method, with PayPal planned — [Productrise](https://productrise.app/blog/ucp-rollout-update); [commercetools](https://commercetools.com/blog/google-ucp-merchant-guide-to-agentic-commerce) (secondary; rollout details conflict)
- **OpenAI/Stripe Agentic Commerce Protocol (ACP) and Instant Checkout:** on **17 Mar 2026** OpenAI scaled back native Instant Checkout in ChatGPT and shifted purchases to retailer apps such as Instacart, Target and Expedia. ACP was repositioned as merchant-connection infrastructure. Reported reasons were that users research but do not buy in ChatGPT, only ~12 Shopify merchants went live, and merchant-of-record sales-tax infrastructure was missing — [Modern Retail](https://www.modernretail.co/technology/what-went-wrong-with-chatgpts-instant-checkout/); [Forrester](https://www.forrester.com/blogs/what-it-means-that-the-leader-in-agentic-commerce-just-pulled-back/); [Rye](https://rye.com/blog/openai-chatgpt-checkout-agentic-commerce). Forrester cites OpenAI language calling it "temporary", while others call it a termination.
- **Google AP2 (Agent Payments Protocol):** launched Sep 2025 (older) with 60+ collaborators. It uses signed "mandates" that record user intent. Maturity claims conflict, and one claim that AP2 was donated to the FIDO Alliance is uncorroborated — [Crossmint](https://www.crossmint.com/learn/agentic-payments-protocols-compared); [Bitontree](https://www.bitontree.com/agentic-commerce-ai-agents-payments-ap2-x402)
- **Coinbase x402:** v2 shipped Dec 2025, Stripe integrated x402 on Base in Feb 2026, and Cloudflare supports it. A single secondary source reports an **x402 Foundation under the Linux Foundation (Apr 2026)**, which I did not verify — [Reactify](https://www.reactify-solutions.com/articles/agentic-commerce-protocols-2026); [Applied Technology Index](https://appliedtechnologyindex.com/research/2026-comparative-analysis-agentic-commerce-payment-protocols/)
- **Visa Trusted Agent Protocol (TAP):** launched **14 Oct 2025** with Cloudflare (older). It covers agent identity and trust, not cart data, and has reportedly been folded into **Visa Intelligent Commerce** — [Eco](https://eco.com/support/en/articles/15192003-mastercard-agent-pay-vs-visa-trusted-agent-2026-compared)

## 4. Best practices for MCP servers that execute consequential (write) actions

### Takeaway
The converging guidance from the spec, Anthropic's directory rules, OWASP and security research is:
- Use per-user delegated OAuth: PKCE, audience-bound tokens, no token passthrough.
- Strictly separate read and write tools, annotated with `readOnlyHint`/`destructiveHint`, since clients use these to auto-approve reads and always prompt on destructive calls.
- Use step-up scopes and human confirmation for high-impact actions; MCP Apps and URL elicitation give a standard confirmation and preview surface.
- Return explicit state handles (stateless 2026 spec) and use Tasks for long-running jobs.
- Defend hard against tool poisoning and prompt injection.
- Prefer fewer, higher-level, well-described tools. Use "code mode" for very large API surfaces.

### Cited Findings
**Authorization and identity**
- Claude's client sends **PKCE S256** on every request. It requires a **401 with `WWW-Authenticate: Bearer resource_metadata=...`** (RFC 9728 protected resource metadata), whose `resource` must exactly equal the MCP URL. It uses only the first `authorization_servers` entry. Servers steer requested scopes via `scope` in the 401 `WWW-Authenticate` header, and Claude adds `offline_access` if advertised. Refresh tokens must be rotated for public clients (DCR/CIMD), revoked tokens must return `invalid_grant`, and the token endpoint must accept form-urlencoded. Latency budgets are 10s (discovery, registration, token) and 30s (refresh). Static org API keys must never go in URL query strings, because the MCP spec prohibits tokens in query strings. "Lazy authentication" lets public tools work before sign-in — [Claude docs: Authentication](https://claude.com/docs/connectors/building/authentication)
- For enterprises, Anthropic says to "scope what each user can reach with your service's own per-user permissions rather than with a per-tenant OAuth app". Enterprise Managed Auth accepts IdP-signed identity assertions without a consent screen. Anthropic's egress range is `160.79.104.0/21` for allowlisting — [Claude docs: Authentication](https://claude.com/docs/connectors/building/authentication)
- 2026-07-28 adds mandatory `iss` validation (RFC 9207), issuer-bound client credentials and step-up **scope accumulation** — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)
- The MCP spec **forbids token passthrough**: servers should accept only tokens whose audience is the MCP server itself — [Corgea](https://corgea.com/learn/mcp-security-best-practices). **Confused-deputy** risk arises when a server acts with its own broad privileges rather than the user's. Mitigations include per-client consent, exact redirect-URI matching and signed state — [OWASP MCP Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html); [mcpservers.org blog](https://blog.mcpservers.org/posts/mcp-security-best-practices)
- Show the redirect URI hostname on consent screens, with an extra warning for loopback-only clients, per the MCP auth spec as cited by Claude docs — [Claude docs](https://claude.com/docs/connectors/building/authentication)

**Tool design for write actions**
- Claude's directory **rejects a catch-all tool mixing safe and unsafe HTTP methods**, such as `api_request` with a `method` param. Write tools should be split further into create, update and delete. **`readOnlyHint` tools can run without per-call confirmation, while `destructiveHint` tools always prompt.** Tool names must be ≤64 chars and descriptions must match behavior. Custom query tools must name or link the target API's docs. Errors must be actionable rather than a generic 500/400, responses should be reasonably sized, and servers must not read Claude memory or chat history — [Claude docs: Review criteria](https://claude.com/docs/connectors/building/review-criteria)
- Anthropic's tool-design guidance recommends **consolidating** tools around real workflows (e.g., find availability and book in one tool rather than separate list and create calls), **namespacing** tools (prefix vs suffix effects vary by model, so evaluate), and returning high-signal output, optionally with a `response_format` (concise/detailed) parameter — [Anthropic Engineering: Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents); [HowAIWorks summary](https://howaiworks.ai/blog/anthropic-writing-tools-for-agents) (response_format detail from secondary)
- Stateless 2026 spec: application state is carried via explicit handles like `basket_id`. Long-running operations return a **task handle** managed with `tasks/get`, `tasks/update` and `tasks/cancel` — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)
- **URL-mode elicitation** is the spec's channel for payment processing and sensitive operations — [MCP spec mirror](https://modelcontextprotocol.net/specification/draft/client/elicitation). Form mode is reportedly prohibited for credentials and payment data in 2026-07-28 — [yage.ai](https://yage.ai/share/mcp-elicitation-human-in-loop-en-20260716.html)
- Security guides converge on requiring explicit human approval for destructive or sensitive operations, least-privilege scopes, version pinning and signature checks for third-party servers, and audit logging of tool calls — [OWASP MCP Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/MCP_Security_Cheat_Sheet.html); [Sim.ai](https://www.sim.ai/library/mcp-security); [Practical DevSecOps](https://www.practical-devsecops.com/mcp-security-best-practices/)

**Prompt injection and tool poisoning**
- The **OWASP Top 10 for Agentic Applications** was released Dec 2025 (often labelled "2026"). It includes ASI01 Agent Goal Hijack and ASI04 Agentic Supply Chain Vulnerabilities, and recommends treating retrieved content as untrusted and using signed components — [Cycode](https://cycode.com/blog/owasp-top-10-agentic-applications/); [Promptfoo](https://www.promptfoo.dev/docs/red-team/owasp-agentic-ai/)
- A separate **OWASP MCP Top 10** (beta) covers token mismanagement, **tool poisoning** (MCP03: malicious instructions in tool descriptions, schemas or return values), shadow MCP servers and context over-sharing. Suggested defenses include **pinning and hashing tool descriptions on first approval and re-prompting on change** — [OWASP GitHub](https://github.com/OWASP/www-project-mcp-top-10); [Cycode](https://cycode.com/blog/owasp-mcp-top-10/); [MCP Playground](https://mcpplaygroundonline.com/blog/mcp-security-tool-poisoning-owasp-top-10-mcp-scan). Microsoft maps it in its agent-governance-toolkit — [Microsoft GitHub](https://github.com/microsoft/agent-governance-toolkit/blob/main/docs/compliance/mcp-owasp-top10-mapping.md)
- Reported evidence (secondary): Palo Alto Unit 42 measured a **78.3% attack success rate** with five MCP servers connected to one agent, and **30+ CVEs** were filed against MCP servers, clients and infrastructure in Jan–Feb 2026 — [Practical DevSecOps](https://www.practical-devsecops.com/owasp-mcp-top-10/); [MCP Playground](https://mcpplaygroundonline.com/blog/mcp-security-tool-poisoning-owasp-top-10-mcp-scan) (primary Unit 42 report not fetched)
- Claude's directory rejects descriptions that instruct Claude to call unrequested tools, interfere with other tools, pull behavioral instructions from external sources, contain hidden or encoded instructions, or promote products — [Claude docs: Review criteria](https://claude.com/docs/connectors/building/review-criteria)
- 2026-07-28: implementations MUST NOT auto-dereference external `$ref` in tool schemas — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

**Token efficiency and "code mode"**
- **Cloudflare Code Mode** exposes the entire Cloudflare API via **two tools (`search()`, `execute()`) in ~1,000 tokens**, against an estimated ~1.17M tokens for one-tool-per-endpoint (~2,500 endpoints) — [Cloudflare blog](https://blog.cloudflare.com/code-mode-mcp/)
- Anthropic's "code execution with MCP" post (reported date **4 Nov 2025**) cut a Drive→Salesforce workflow from **150,000 to 2,000 tokens (−98.7%)** by having the agent write code against MCP tools — [Maxim (secondary)](https://www.getmaxim.ai/articles/code-execution-with-mcp-how-code-mode-cuts-agent-token-costs-by-90/). One critic says the 1.17M baseline is hypothetical and that **under ~10 tools code mode is a net loss** — [ContextBolt](https://contextbolt.com/blog/code-mode-mcp/)
- 2026-07-28 adds `ttlMs`/`cacheScope` caching hints on list and read results — [MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/)

### Inferences
These are not found as explicit sourced guidance in this research and are recommended from established API practice. Treat them as design recommendations, not cited facts.
- **Idempotency keys** on every write tool (e.g., `client_request_id`) so retries from MRTR, Task polling or model re-tries do not double-submit invoices or payments. This is more important under the stateless 2026 spec, where any instance can receive a retry.
- A **two-phase "prepare → confirm" pattern**: a `*_preview` or `dry_run` read-only tool returns a diff or summary plus a short-lived confirmation handle, and the destructive tool requires that handle. This lines up with Claude's auto-prompt on `destructiveHint`, and an MCP Apps preview card can render the confirmation.
- A **per-tenant credential vault** (envelope encryption, per-connection refresh-token rotation), **append-only audit logs** keyed by user, agent client ID (CIMD URL) and tool call, and per-user/per-tenant **rate limits**. These matter more in Malaysia given PDPA 2010 (amended 2024) obligations; that is a regulatory linkage not researched here.
- Tool count: keep a curated set of roughly 10–30 workflow-level tools per vertical. Reserve code mode or search+execute for "long-tail API" access, but that pattern collides with Claude's rule against catch-all mixed read/write tools, so keep separate read and write `execute` tools.

### Gaps
- No primary MCP-spec text was retrieved for the security best-practices page (DNS failure), so token-passthrough and confused-deputy claims are from secondary summaries and OWASP.
- No authoritative source was found that prescribes idempotency keys or dry-run for MCP specifically.
- The primary Unit 42 report and Anthropic's code-execution post were not fetched.

## 6. Risks (incumbent first-party MCP, model-vendor native integrations, wrapper commoditization) and durable moats

### Takeaway
"API wrapper" MCP servers are **rapidly commoditizing**. Large payments, commerce and accounting incumbents now ship **official remote MCP servers** (Stripe, PayPal, Xero; Shopify partially). Directories favor first-party servers (Claude requires first-party or legitimately proxied APIs and the domain match). Horizontal platforms already list thousands of tools. Durable moats for a Malaysian layer are therefore: (1) **licenses, approvals and partner permissions** to act on regulated rails such as banks, LHDN and e-wallets; (2) **compliance logic** (e-invoice validation, SST, statutory payroll) that turns APIs into correct outcomes; (3) **trust infrastructure** (consent, step-up, audit, PDPA-grade data handling) that enterprises and directories require; (4) **local distribution** through Malaysian banks, accounting firms and SME platforms; and possibly (5) **data/network effects** like Pagero's.

### Cited Findings
- **Incumbents' first-party servers:** Stripe hosts a remote OAuth MCP server at `mcp.stripe.com`, plus a local option and an agent toolkit — [PulseMCP](https://www.pulsemcp.com/servers/stripe-agent-toolkit); [mcpservers.org](https://mcpservers.org/servers/stripe-mcp-server). PayPal offers official local (Agent Toolkit) and remote MCP servers, with sandbox at `mcp.sandbox.paypal.com/http` — [PayPal Developer quickstart](https://developer.paypal.com/ai-tools/mcp-server); [PayPal Community Blog](https://developer.paypal.com/community/blog/paypal-model-context-protocol/). Xero publishes an official `XeroAPI/xero-mcp-server` — [VoltAgent official MCP list](https://github.com/VoltAgent/official-mcp-servers). Shopify is contested: one source lists four official servers (Storefront, Customer Account, Checkout, Dev), while a Sep 2026 test found per-merchant storefront MCP at `/api/mcp` and admin tasks served only by community wrappers — [Your Next Store](https://yournextstore.com/blog/mcp-servers-for-ecommerce); [AgentsPay](https://agentspay.ai/vs/payment-mcp-servers)
- A curated directory counts **280+ official (vendor-built) MCP servers** — [VoltAgent](https://github.com/VoltAgent/official-mcp-servers)
- **Directory policy favors first parties:** Claude's directory requires calling "your own first-party APIs, or APIs you legitimately proxy" with "the MCP server domain [matching] your service". It asks whether a proxied API is used "with permission", and it bars money-transfer connectors — [Claude docs: Review criteria](https://claude.com/docs/connectors/building/review-criteria); [Claude docs: Submit](https://claude.com/docs/connectors/building/submission)
- **Model-vendor and platform encroachment in commerce:** Google's UCP and OpenAI's ACP are platform-owned commerce protocols. OpenAI's retreat (Mar 2026) was attributed partly to missing **merchant-of-record tax infrastructure** across US states, which shows that **compliance plumbing is hard even for model vendors** — [Modern Retail](https://www.modernretail.co/technology/what-went-wrong-with-chatgpts-instant-checkout/); [Rye](https://rye.com/blog/openai-chatgpt-checkout-agentic-commerce)
- **Breadth commoditized:** Composio 1,000+ apps, Nango 7,000+ tools, Arcade 8,000+ tools, Zapier 40,000+ actions — sources as in §5 ([Merge](https://www.merge.dev/blog/composio-vs-arcade), [Nango](https://nango.dev/blog/composio-vs-nango/), [Arcade](https://www.arcade.dev/blog/), [GTM Directory](https://thegtmdirectory.com/compare/pipedream-vs-zapier))
- **Network/compliance moat evidence:** Pagero's value rested on mandate compliance in 75+ countries and a 14M-company network — [Thomson Reuters Europe](https://europe.thomsonreuters.com/newsroom/thomson-reuters-successful-acquisition-of-pagero-paves-the-way-for-significant-growth-opportunities)
- **Local rails are getting agent-ready via incumbents:** Mastercard Agent Pay pilots with **CIMB and RHB** in Malaysia, and Visa Agentic Ready is live in Malaysia (Apr 2026) — [Stellagent](https://stellagent.ai/insights/visa-agentic-ready-programme-asia-pacific); [Whitesight](https://newsletter.whitesight.net/p/agentic-finance-mastercards-agent-ae4) (secondary)
- **Security as differentiator:** high attack-success rates and 30+ MCP CVEs (early 2026) make audited, injection-resistant servers a buying criterion — [Practical DevSecOps](https://www.practical-devsecops.com/owasp-mcp-top-10/)

### Inferences
- **Highest risk:** generic wrappers of APIs whose owners will ship their own MCP. These include Xero, Stripe, PayPal and Shopify, and likely Malaysian SaaS such as accounting and HR platforms, and eventually banks. Any tool the startup ships for these should add cross-system orchestration or compliance value, not mirror endpoints.
- **Model-vendor risk:** model vendors are unlikely to build Malaysia-specific statutory integrations (LHDN MyInvois, KWSP/PERKESO/EIS, SSM, JPJ, DuitNow request-to-pay) given small market size. The risk is that **local incumbents** (banks, payment gateways, accounting SaaS) ship first-party servers, and that horizontal platforms add Malaysia connectors as long-tail catalog entries.
- **Moats in rough order of durability for Malaysia:**
  1. Regulatory approvals and partner agreements: e.g., Peppol/MyInvois service-provider status, BNM-related licensing or partnership to initiate payments, bank partnerships for agent tokens.
  2. Encoded compliance logic and validation, such as MyInvois schema, SST/e-invoice rules and payroll statutory rates, kept current as rules change.
  3. Trust/audit infrastructure: consent records, step-up confirmation, per-action audit, PDPA alignment.
  4. Distribution partnerships: accounting firms, banks' SME portals, Malaysian SaaS app marketplaces.
  5. Being the "first-party-adjacent" legitimate proxy, with written permissions that satisfy directory review.
- **Distribution strategy implied:** list as a first-party connector for the startup's own value-add API (compliance/validation/orchestration), not as a proxy of others' APIs. Pair it with SKILL.md playbooks. Offer white-label MCP endpoints to Malaysian incumbents, who need one to appear in Claude, ChatGPT and Copilot directories under their own brand, so incumbents become customers rather than competitors.

- No evidence was found on whether Malaysian incumbents (Maybank, CIMB, LHDN, Touch 'n Go, local accounting SaaS such as SQL Account, AutoCount or Bukku) have shipped or announced MCP servers. This is not covered here and should be checked by the Malaysia-specific researcher.
- No source quantifies how quickly first-party MCP servers displaced third-party wrappers (e.g., listing or usage share in directories).
- No primary evidence was found on whether Claude or ChatGPT directories accept "legitimate proxy" aggregator connectors in practice, beyond the policy text.
