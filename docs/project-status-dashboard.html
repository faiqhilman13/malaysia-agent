Architecture Status

The system now has five practical layers: agent entrypoints, action contracts, workflow and approval state, provider adapters, and presentation surfaces. The browser layer is served by the same local server as the API so the workbench can call live endpoints without extra glue.

Dependency reality

  • Core engine: strong enough for demos, pilot shaping, and vertical workflow experimentation.
  • MyInvois: live code path exists, but needs sandbox or production credentials plus compliant payloads.
  • CIDB: live code path exists, but needs bearer token access.
  • Halal: strongest local workflow model, but official MYeHALAL or MyHALALINGREDIENTS write access is still relationship-gated.
  • Frontend: local-only operator surface, not deployed multi-user SaaS yet.
  • Healthcare: still roadmap only. No clinical integration code yet.
