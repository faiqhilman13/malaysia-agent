How It Works

Three Layers, One Contract

A deliberate separation that keeps the action contract stable while adapters connect to new Malaysian rails as they become available.

01

Action Contract

Stable action names and a uniform JSON request/response format. This is what agents depend on -- it does not change when the underlying provider changes.

02

Workflow Orchestration

Stateful business logic -- status transitions, validation rules, exception handling, and coordination between multiple actions. Durable and resumable.

03

Provider Adapters

Connects to external systems. Each adapter handles authentication, payload translation, and API specifics. Sandbox and live modes in parallel.

Agent-First Design

Every Response Tells the Agent What to Do Next

A consistent JSON envelope across all 45 actions. Status, next_action, and blocking_reason in every response -- so agents chain operations without custom parsing.

Uniform Envelope
Every action returns status, next_action, blocking_reason, source_system, resource_id, timestamp, and data.
Four Surfaces
CLI, HTTP API, stdio MCP server, and repo-local agent skill -- all invoking the same service layer.
Zero Dependencies
Python stdlib only. SQLite for state. No supply chain risk.
Sandbox Parity
Every production workflow has an equivalent deterministic sandbox path for testing.

Roadmap

Phased Execution

Each phase expands what agents can autonomously execute against Malaysian systems.

Phase 0

Contract & Sandbox Core

Stable action envelope, SQLite persistence, CLI and HTTP parity.

Phase 1

Autonomous Runner & Approvals

workflows.run, state history, approval store, event-driven payments, MCP server.

Phase 2

MyInvois High-Level Execution

invoices.* delegating to real LHDN rails. Live sandbox tested, production gated on credentials.

Phase 3

Halal Precheck Reports

Source-grounded manufacturer and food-premise dossier checks with JSON, Markdown, and HTML output.

Phase 4

PayNet & DuitNow Settlement

Real payment rails -- partner-backed settlement adapters and callback infrastructure.

Phase 5

MyDigital ID & Delegated Authority

Cryptographically bound approval identity for sensitive workflows.

Phase 6-8

Trade, Halal Regulator, Healthcare

DagangNet/NSW live execution, JAKIM integration, DRG and ICD-10 revenue cycle.

Quickstart

Running in Three Steps

Zero dependencies. Pure Python stdlib. Works in any environment with Python 3.11+.

01
Start the server
$ python3 manage.py serve \
  --host 127.0.0.1 --port 8080
02
Submit an invoice
$ python3 manage.py action \
  invoices.submit \
  --json '{...}' --pretty
03
Run a full workflow
$ python3 manage.py action \
  workflows.run \
  --json '{...}' --pretty
